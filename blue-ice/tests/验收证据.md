## 3. 难度曲线诊断（三次独立采样）

```
$ REPEAT=3 python tests/balance_probe.py
Exit Code: 0
```

| 玩家画像 | 胜率 | 平均剩余链路 | 三次结果 |
|---|---|---|---|
| 高手（每 2s 决策 / 大量合成部署） | 1.00 | 100.0 | win / win / win |
| 普通（每 5s / 每轮 2 次部署） | 0.67 | 66.7 | win / win / lose |
| 新手（每 8s / 每轮 1 次部署 / 半数概率合成） | 0.67 | 66.7 | win / win / lose |
| 完全不操作 | 0.00 | 0.0 | lose(第 6 波) ×3 |

`balance_report.json` 含每次运行的逐波时间轴（波次开始时间、链路、塔数、最高等级）。
节奏实测：前 8 波约每 20 秒一波（含 9–14 秒准备期，玩家可「立即开始」跳过），第 9 波起升压，BOSS 战持续约 25–30 秒。

**结论的边界**：抽卡随机导致结果存在波动，因此采用三次采样而非单次结论；脚本模拟的「玩家」始终执行最优部署/合成，只改变操作频率，不等同于真人决策差异。

### 迭代过程（可追溯）
| 版本 | 改动 | 诊断结果 |
|---|---|---|
| v1 | 初始数值 | 四类有操作玩家全部 `link=100` 满血通关 → 无张力，判定不合格 |
| v2 | 敌血成长 0.18→0.38、速度/漏网伤害提高、经济收紧、等级倍率下调 | 仍全部满血 |
| v3 | 可放置钻孔 28→17 | 仍全部满血，定位到经济过剩 |
| v4 | 击杀奖励减半、部署成本每 5 次 +5 | 仍全部满血，定位到 BOSS 与后段压力不足 |
| v5（定稿） | 第 9 波起额外升压、BOSS 血量 5200→12000、脉冲禁用 2→3 座且间隔 6.2→4.8s | 出现胜率分层，BOSS 战成为真实考验 |

## 6. 证伪栏

若「第一关完整可玩且达标」为假，最可能假在：
1. **真机兼容**：只在 Chrome 桌面与移动模拟验证 → 用手机真机打开局域网地址手动试玩可排除。
2. **胜负流程真实性**：`advance()` 是固定步长快进，不是人手打 12 波 → 手动打一局，或核对 `test_report.json` 断言与截图可排除。
3. **手感与难度**：脚本玩家不等于真人 → 亲自试玩并对照 `balance_report.json` 的逐波时间轴。
4. **音效质量**：只验证初始化 → 实际听部署 / 合成 / BOSS / 胜利音效。
5. **视觉主观判断**：直接查看 `screenshots/` 实拍图，不以文字描述为准。
